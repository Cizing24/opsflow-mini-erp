# ADR-001：單體交易、固定成本與本機隔離

狀態：Accepted。日期：2026-11-20（Asia/Taipei）。

## 背景與決定

本作品的難點是跨部門單據一致性，而非服務拆分。採 Vue + NestJS + MySQL Modular Monolith，以 Prisma transaction 管理寫入。不用微服務、事件最終一致性或外部認證服務，縮小可重現測試與本機啟動的負擔。

使用整數 cents，單筆請購／領料成本上限 2,000,000,000 分；專案預算輸入上限 1,000,000,000 分。固定標準成本讓收貨、庫存與領料的口徑一致，尚不提供價格變更或移動平均估價。這是明確的產品界線，不能宣稱具備完整會計成本功能。

## 替代方案與影響

SQLite 不能替代本次 MySQL 的真實並行驗證；Mock repository 不能作為交易測試證據。以 MySQL 列鎖及條件 UPDATE 保護競爭點，比應用層 mutex 可處理更多連線且有明確 rollback 邊界。額外採用新 Nest 12 或 Prisma 8 RC 對核心流程沒有必要收益，因此鎖定已實測版本。

預算核准採 Request → Project 鎖順序。此決定來自 Issue #5 的實際競態重現；必須先讀取受鎖保護的最新版明細。後續新增會修改多張請購／專案的操作，需沿用一致的鎖順序並新增並行測試。

Session 與 rate limit 為單一 app instance；DB session 可共享，但 rate limit 使用記憶體。若要部署多副本，需先改為共用 limiter 或在可信任 gateway 限流。原始公開資料採離線轉換、明確 CLI 匯入，ERP 啟動不依賴下載成功。
